## 2. 他担当の主張で疑わしい点・矛盾点

1. **従業員数**:依頼文は約60名、現の検索要約は94名(2026年4月時点)。規程に人数を書かず、94名ならKの工数上限を見直す。要確認。
2. **法の内部不整合**:結論は名簿を原則AI投入禁止だが、P1表は「条件付(承認ツール+匿名化)」。Eで「禁止+ダミー置換後可」に統一を提案。
3. **経の「自治体雛形は禁止リスト型」**:根拠が弱い。私の第1ラウンドの二次情報では、東京都は学習されない環境の利用を前提とするルール+事例で、型の断定は確認できない。要確認。
4. **懐の「都のガイドラインは69頁」**を多層批判に使うのは不適切。事例編を含む頁数で、ルール部分は「4つのルール」(二次情報)。私案の層は分量でなく改廃頻度の分離が目的。
5. **私物端末**:法は「私用端末・私的利用の規律は不要」、保は制限、経・現は含める、と割れている。私案は、私的利用は対象外、端末を問わず区分B以上の入力を規律し、私物での承認ツール利用可否は別表1で定める。
6. **経の「役員も同じ規程に従う」**:役員は労働者でなく就業規則・懲戒の対象外(私見・要確認)。適用しても違反時措置は取締役会等の定めになる。
7. **個情法改正**:法は罰則強化を公布6か月後(2027-01-17)、他担当は「公布から2年以内」とし、いずれも二次情報。規程に条番号・施行日を書かず「関係法令」とする。AI事業者ガイドラインを根拠にしても「義務」とは書かない(「トレーサビリティ義務化」は誇張、人の指摘)。
8. **助成金・補助金の要件**(人、経)と**シャドーAI統計**(46.9%、73.1%、約4割、73%、母集団が異なる)は一次未確認。規程設計の前提にせず、規程・前文に数値を書かない。

## 3. 撤退ラインとレッドライン

**撤退ライン**
1. 本則はA4×3枚から2枚(約2,500字・10〜12条)まで圧縮可(レッドラインの条項は残す)。
2. 基本方針の別文書化、運用基準の規程化(細則化)、条文ごとのかんたん解説を取り下げる(手引き扱い)。
3. 現場3色を正式な表示とし、4区分は別表2内の細分とする。法務がNDA上の包括秘密と判断すれば、原価・単価をCからDへ移す。
4. 派遣・パートの確認を「誓約」形式にすることを許容(人・法が効力と拒否時の扱いを整理した場合)。
5. 回答期限・保存期間・ログ項目などの数値は全て運用手順へ移し、変更可とする。

**レッドライン**
1. 懲戒の構成要件(禁止行為)は本則だけで読めること。別表は具体化にとどめ、懲戒対象は本則列挙に限る(緩和は即時、厳格化は周知後に発効)。
2. ツール名・モデル名・数値・設定値・法令の条番号を本則に書かない。
3. 条文化できない・測れない義務を書かない(「適切に」等の未定義語、本則での「望ましい」)。
4. 例外・新規ツールの手続(受付、回答責任、期限付き承認、記録)と、改廃・版管理(権限者、周期、施行日、周知期間、履歴)を文書内に置く。
5. 適用対象ごとに実効手段(就業規則/派遣元/契約/役員の定め)を特定する。直接適用できない者に「従え」とだけ書かない。

## 4. 合意案の骨子

1. 3層:本則(義務のみ、A4×3枚、17条)/別表(ツール、区分、事例、案件、連絡先)/手引き(1枚もの、FAQ、運用手順、様式)。
2. 業務情報の入力は承認済みサービスのみ可。個人アカウント・私物端末への区分B以上の入力は禁止(区分Aのみ未承認可)。
3. 区分D(個人データ、未発表デザイン、NDA・ライセンサー提供データ、認証情報)は入力禁止。例外は書面承諾+承認ツール+管理責任者承認。
4. 出力は人が確認し、責任は利用者と会社が負う。成果物は類似確認。実在人物・既存エンブレムの模倣生成は禁止。
5. ライセンス品・NDA案件は既定でAI不可、書面許可のみ。顧客向けAI機能と自動実行機能は事前承認。
6. 顧客:ラフは包括注記、新規マーク制作は個別開示+再構成+記録。新規ツール・例外は届出/申請、期限付き承認、記録。
7. 報告は直ちに・24時間以内。不利益取扱い禁止。誠実な過失は指導・再教育。懲戒は本則の構成要件で就業規則に接続。
8. 適用手段:正社員・パートは就業規則+受領確認、派遣は派遣元経由、委託は契約別紙、役員は取締役会の定め。
9. 体制:社長、AI管理責任者+代理、役割アドレス、年100人時以内。教育は全員15分+受領確認で、アカウント付与の条件。
