# 主張書(情報セキュリティ担当/CISO視点)小西マーク株式会社 AI利用規程

作成日: 2026-10-03 / 担当: 情報セキュリティ

**調査上の制約(先に明記)**
- IPA・経産省・総務省・個情委・国家サイバー統括室など日本政府系サイトは遮断され、本文を取得できなかった。これらは検索結果の要約(二次情報)で確認したのみで、本書では「一次未確認」と付す。
- 本文を直接確認できたのは、OWASP LLM Top 10 2026(GitHub)、MCP公式仕様のセキュリティ文書(GitHub)、Anthropic/Claude Code公式文書、Microsoft公式ブログ等。ベンダー記述は評価基準の具体例としてのみ使い、特定製品の推奨ではない。
- 検索回数の上限に達したため、AI議事録・画像生成AI・営業秘密・保険は追加調査できず、私の一般知識(未検証)で書いている。該当箇所は「私見」と付す。
- 区分の凡例: 【義務】法令・契約上の義務 / 【官推奨】官公庁の指針・注意喚起 / 【BP】業界のベストプラクティス / 【私見】私の判断。

## 1. 結論(推奨スタンス)

1. **「全面禁止」でも「自己責任の自由利用」でもなく、「承認済みツールのみ業務利用可+情報区分別の入力ルール+少数の絶対禁止」を推奨する。** 禁止だけではシャドーAIが地下化し、会社から見えなくなる。
2. **規程本体は短く(原則と責任の定め)、変わりやすいものは別紙に分離する。** 別紙はツール台帳、情報区分表、ベンダー評価チェックリスト、インシデント連絡先。
3. **ルール頼みにせず、安価な技術的担保を組み合わせる。** 会社ID+MFA、法人契約(学習利用なし)、ブラウザ拡張の許可リスト化、既存スイートの共有設定の棚卸し。高額なDLP製品は不要。
4. **自律実行系(AIエージェント、MCP、AIブラウザ、ローカル常駐エージェント、コーディングAI)は当面「原則禁止・申請制」とする。** チャット型の誤入力とは桁違いに被害が大きく、60名規模では統制コストが見合わない。
5. **最大の固有リスクは「取引先から預かる未発表デザイン・版下・入稿データ」の流出である。** 専用の情報区分を設ける。

## 2. 規程に必ず入れるべき事項(優先順位つき)

### P0(初版から必須)

**情報区分×入力可否(別紙案)**

| 区分 | 例 | 入力可否 |
|---|---|---|
| A 公開 | 公開済みカタログ、プレスリリース | 承認ツールで可 |
| B 社内 | 社内手順書、顧客名・単価を含まない文面ひな形 | 承認ツールで可 |
| C 社外秘・取引条件 | 顧客名と単価・納期、原価、仕入先、受領資料 | **Tier A(法人契約・学習なし・SSO)のみ**。必要最小限。 |
| D 禁止 | 個人データ(会員・従業員・要配慮)、認証情報・鍵、NDA対象の未発表デザイン・版下・入稿データ、AI利用を禁じる契約の対象情報 | **入力禁止**。例外は経営者承認、取引先の書面許諾、Tier A、ログ保存が全て揃う場合のみ。 |

注: 「担当者の氏名・社名を含む通常の業務メール文面」をCかDのどちらに置くかは法務判断(個人データの提供・委託の整理)。私見は「Tier Aに限り最小限は可、他は仮名化」。

**インシデント初動(別紙案)**
1. 気づいた人は操作を止める(エージェントなら停止・ネット切断)。**自分で履歴を消さない**(証跡保全。私見)。
2. 上長とAI管理窓口へ即報告(目安は当日中、夜間休日は連絡網)。疑いの段階でも報告し、免責する。
3. 窓口が一次評価(どのツールのどのプランか、個人データ・取引先秘の有無、いつ・何を)。
4. 封じ込め: パスワード変更、トークン失効、連携解除、共有リンク停止、ベンダーへ削除依頼と学習オプトアウトの確認。
5. 経営・法務判断: 個情委報告・本人通知の要否(個情法26条: 速報は発覚後3〜5日目安、確報は30日以内、不正目的は60日以内。私の知識で未検証)、取引先への通知(契約確認)。
6. 台帳更新、再発防止。

### P1(半年以内に導入)
- **ベンダー評価チェックリスト**(10項目程度): 学習利用の有無を契約か設定で確認、データ保管国と当該国の政府アクセス法制、保持期間と削除手段、SOC 2またはISO 27001(代替可)、SSO/MFA/管理者機能、監査ログ、再委託先、事故通知、規約変更通知。中国等へデータが保存されるサービスの扱いは、個情委が2025/2/3にDeepSeekで注意喚起した(二次確認)。別紙のブロックリスト掲載は妥当(私見)。**ログ・SCIM等が上位プランのみの製品がある**(Claude公式料金ページ、2026/10/3取得: Teamに監査ログ・SCIMなし)。評価は機能と予算の両面で行う。
- **ブラウザ拡張・AI機能内蔵SaaS・議事録AI・画像変換の棚卸し**。既定はOFF。議事録AIは、社外参加者がいる会議やNDA案件では事前告知と同意なしに使わない(私見、法務確認)。
- **AIブラウザ(自律ブラウジング型)は当面禁止**。Gartnerは2025/12に当面ブロックを推奨(二次確認)。Anthropicが自社試験で公表した、緩和前の攻撃成功率23.6%・緩和後11.2%(2025年当時、確認済み)は、ベンダー自身が未解決と認める根拠になる。
- **端末**: 会社貸与端末を原則とする。私物端末は承認ツールのブラウザ利用のみ可で、ローカルアプリ・エージェント・業務データの保存は不可(BYOD)。
- **教育**: 入社時と年1回、各15分。内容は「入れてはいけないもの」の事例クイズ。

### P2(余力があれば)
- 外注先・フリーランスとの契約・覚書にAI利用条項(入力禁止区分、再委託、事故通知)を追加。
- AIを使った詐欺への備え。ディープフェイク音声や自然な日本語のフィッシングによる取引先なりすましに備え、振込先変更・緊急依頼は別経路で確認する。IPAも攻撃の高度化を指摘(二次確認)。
- 外注開発者のAIコーディング利用条件。生成コードのレビュー、認証情報を貼らない、依存パッケージの検証。npmでは2025/9に500超、2026/8/4の波で400超のパッケージが汚染された(二次確認)。

## 3. 入れるべきでない/やりすぎになる事項

- **全面禁止**: ガートナー調査(従業員の57%が個人AIを業務利用、二次確認)が示すように地下化する。
- **製品名・設定値・CVE番号を規程本文に書く**: 陳腐化が早く、改定のたびに承認手続きが要る。別紙に出す。
- **全プロンプトの事前承認、全出力の二重チェック**: 守られず、形骸化する。確認は高リスク用途に限る。
- **プロンプトの常時全件監視、私用スマホの監視**: 労務・プライバシー面の負担が大きい。ログは事故時調査と定期レビューに限る(人事・法務と調整)。
- **ISO 27001/42001認証やSOC 2を全ベンダー必須にする**: 中小SaaSを一律に排除し、使えるツールが無くなる。契約・DPA・設定での補完を認める。
- **高度なDLP・CASB・SIEMの要求**: 60名・情シス不在では運用できない。ブラウザ管理、DNS/UTMのカテゴリブロック、スイート標準の共有制限で十分(私見)。
- **実現不能な約束**: 「入力情報は完全削除される」「漏えいゼロ」。
- **過度に重い罰則の列挙**: 報告が萎縮し、インシデントが隠れる。
- **著作権・肖像・EU AI Act等の網羅**: 法務の担当で、セキュリティ章に混ぜない。

## 4. 小西マーク固有の論点

1. **取引先の未発表情報**: プロ野球・サッカー日本代表等のマーキング受注は、新ユニフォームの発表前情報が最重要の営業秘密になり、NDAやライセンス契約の対象と推測される(契約は未確認)。区分Dを設け、AIへの入力を原則禁止とする。写り込みにも注意する(現場スマホで不良品や版下を撮ってAIに送る行為)。
2. **画像のAI処理(背景除去・ベクタ化・アップスケール・生成)が最大のシャドーAI発生源になる(私見)**: 校章・社章・ロゴのトレース需要が高く、無料の海外Webツールに顧客ロゴや生徒・個人の画像、名入れの氏名・背番号(個人データ)を上げてしまう恐れがある。禁止だけでなく、承認済みの代替ツールを用意することが条件。
3. **工場・現場端末**: 刺繍機、昇華プリンタ、CAD/データ制御PCにAI機能・拡張・エージェントを入れない(OTの原則: 外部接続の最小化、私見)。共有アカウントの現場PCでは個人アカウントのAI利用を不可とする。
4. **EC(MARKESTRA)**: 会員・注文情報を含む。サイト改修を外注している場合は、委託先のAIコーディング利用を契約で管理する。AIチャットボットや問い合わせ自動応答を導入するなら別審査とする(カード情報の非保持は前提、未確認)。
5. **既存スイートのAIは「権限の棚卸し」が先**: M365 CopilotやGeminiは既存のアクセス権を前提に動き、緩い共有フォルダ(版下データ置き場等)があるとそこを検索対象にしてしまう。Copilotでは細工メールによるゼロクリック漏えい(EchoLeak, CVE-2025-32711)が報告された(二次確認)。導入前に共有設定を点検する。
6. **取引先の質問票への対応**: 経産省SCS評価制度の★3(26要求事項、★4は43、二次確認)は2026年度末(2027/3頃)に運用開始予定で、任意の制度だが取引条件化の可能性がある。AI規程を「入力ルールと記録」の証跡として使える。
7. **繁忙期の派遣・パート増**: 周知を初日に組み込み、アカウント付与基準を明確にする。

## 5. 他の担当への懸念と要求

- **法務へ**: ①個人データの生成AI入力は提供・委託のどちらに当たるか、クラウド例外の整理。②2026年個情法改正(報道では7月成立、AI学習向け特例と課徴金、二次確認)の影響と施行時期。③営業秘密の秘密管理性への影響。④NDA/ライセンス契約の棚卸し(AI・クラウド利用の制限条項の有無)。⑤議事録AIの録音・同意。⑥漏えい報告の閾値(個情法26条)の確認。
- **現場実務へ**: 使っている無料ツールを責めずに洗い出してほしい(ヒアリング、可能ならブラウザ履歴の簡易調査)。許可ツールで解決できる用途を提示しないと、禁止は守られない。画像処理の代替ツール要件を出してほしい。
- **人事労務教育へ**: 自己申告の免責方針、懲戒は故意・重過失・隠蔽に限る設計、ログ確認の目的告知(就業規則・個人情報の取扱い)、派遣元・委託先への周知経路、教育の頻度と記録。
- **経営リスクへ**: 予算(法人プラン費用×人数、設定・棚卸しの工数、外部ITパートナー)、責任者の任命、サイバー保険の免責条件(統制不備)、取引先要求(SCS)の優先度の判断。
- **規程設計へ**: 3層構造(規程=原則、別紙=基準・台帳、手順=チェックリスト)。区分とTier定義は別紙にして規程改定なしで更新できるようにする。「しなければならない」は技術的に担保できる事項に限る。
- **懐疑派へ**: 「規程を作っても守られない」には同意する。だから技術的担保(ID・MFA・拡張管理・ブロック)とセットにする。それでも文書は、事故時の説明責任、取引先質問票、SCS証跡の最低ラインとして要る。「禁止すれば足りる」には反対する。

## 6. 不確実な点・要確認事項

**調査上の不確実性**
- IPA「生成AIおよびAIエージェントを安全に活用するための手引書」(2026年7月)、経産省WG「AIエージェント事業者向け好事例」(2026年9月、検討中)、国家サイバー統括室の2026/5/18注意喚起(AI性能の高度化を踏まえた対策強化)は、題名のみ確認で内容は未取得。規程は半年ごとの見直しを前提にする。
- 各種統計(シャドーAI率、IBMの追加コスト約67万ドル等)とインシデント詳細は二次情報で、数値の再現は未確認。OpenClawは、公開インスタンス13.5万件超・悪意あるスキル多数・Meta社の禁止などが報じられた(二次確認)。
- 2026年個情法改正の施行時期、条文は未確認(法務へ)。

**会社に質問すべきこと**
1. メール・文書基盤はM365かGoogle Workspaceか。ID管理の有無(Entra/Google)。MFAの現状。
2. 情シス担当(兼務含む)と外部ITベンダー。端末台数、MDMの有無、私物利用(BYOD)、在宅勤務の有無。
3. 事務所と工場のネットワーク分離。現場PC・機器制御PCの共有アカウント状況。
4. 現在のAI利用: 契約済みツール、無料版の利用、画像処理ツール、議事録AI、AI搭載のブラウザ・拡張。経営層が把握しているか。
5. 主要取引先(球団・協会・学校・企業)とのNDA・ライセンス・取引基本契約にAI/クラウド利用の制限があるか。取引先からのセキュリティ質問票の受領歴。
6. 個人データの種類と件数(EC会員、顧客担当者、従業員、名入れ)。決済の方式(カード情報の非保持か)。
7. ECサイトの開発・運用体制(外注の有無、AI利用)。
8. 過去のインシデント、サイバー保険の加入、ISMS/Pマーク/SECURITY ACTION宣言の有無。
9. 派遣・委託先の人数と契約形態。
10. 予算の枠(1人あたり月額の上限感)。
